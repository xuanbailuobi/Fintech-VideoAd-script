# 用户脚本集提炼与时长方法

## 来源和适用范围

来源：用户2026-10-28提供的《金融广告脚本收集.pdf》，共32页。已读取各页文字并检查全部页面缩略图，放大核对关键页面。内容包含多语言文案、参考图、生成画面截图、分镜和制作备注；没有播放或验证原始视频，不据此评价生成成功率、真实播放节奏或投放效果。

本文件沉淀写法，不复制品牌参数表。PDF内“换人、加字幕、保持背景、15秒说完”等均为历史案例要求，只用于理解该案例；当前用户要求、当前产品资料及主技能默认规则优先。它不是让助手执行所有旧提示词的任务清单。

## 五类内的可复用结构

| 例子及PDF页码 | 沉淀的写法 | 使用边界 |
| --- | --- | --- |
| 连续问“要不要”与反复拒绝，1–2页 | 重复建立预期，最后改变回答并揭示产品；可单人口播或多人接话 | 若附加游戏、动作与事件推进，可按用户安排为剧情；不固定三次 |
| 多档金额／期限算例，2–3、14、20页 | 用具体例子解释抽象信息，可配白板或手势 | 30秒版未必适合同时读三个完整算例；每条数据须重新核对 |
| 多个痛点短问后推荐，3、15、20页 | 开头先点出观众困境，再迅速接产品；句子短、问题之间有递进 | 不复制“所有人都适用／所有问题都解决”等绝对话术 |
| 双人轮流、合声开头／收尾，5、16–18、25–28页 | 同一句合声聚焦注意力，交替分别承担信息，旁白插问改变节奏 | 在街头直接讲卖点仍可为口播，不因地点就判为偶遇 |
| 生活困难与家人讨论，10、29页 | 具体家庭任务建立动机，质疑让推荐更自然；分清各人的知情程度 | 家庭通话属于剧情，不是客服电话；不要堆多个问题拖慢产品出现 |
| 街头主持人采访，16页 | 急需资金的选择题 → 找亲友 → 追问失效情形 → 无法回答 → 给出产品选项 | 主持人有明确身份，按采访类；不把普通搭话都叫采访 |
| 树下相遇聊困难，8–9、23页 | 从可见状态搭话，主角说需求，对方推荐，再质疑利息与期限 | 归街头偶遇；产品推荐与主角反应需要连接，不直接跳到庆祝 |
| 商贩整理物品、桌前边整理边回答，23–24、26–27页 | 一个简单生活动作搭配问答，让人物有所处环境；关键回答可暂缓动作并抬眼 | 不连续增加动作，不为每句设计一个新道具；是否采访取决于提问关系 |
| 电话咨询额度、费用与条件，7–8、32页 | 先问当前最关心的问题，再接下一层疑虑，收到回答后有反馈 | 不能把手机号使用年限直接推导成保证获批的普遍规则 |
| 单独或固定分屏的通话，29、32页 | 由参考图约定左右位置、主窗／小窗与人物对应，区分说话者 | 固定分屏不再套逐句全屏切镜；两端不能跨空间递物或目光相接 |
| 猫眼观察催租、内心独白后转向观众，28–29页 | 先用特殊视点交代局面，再借内心想法转入推荐，最后直视镜头CTA | 内心独白用画外音，演员用眼神和动作配合，避免嘴型误配 |
| 三人游戏式拒绝再推荐，30–31页 | 问题与动作建立节拍，拒绝不断累积，最后换人／改语气介绍产品 | 不自动给其他脚本增加身体接触或三人；多人动作要分清先后与参与者 |
| 双人比较后追问，31–32页 | 从差异引出“为什么”，再解释产品、申请条件与CTA | 比较数据需要相同口径；保持用户剧情分类，不新建测评主类 |

## 口播的表现变化不等于新主类

PDF里的绿背景、脱口秀舞台、沙发聊天式、走路自拍、白板讲述、评论回复、多人轮流、动画角色口播，都可放在用户的口播类内，按本次需求使用。不要据此重新扩展主分类。

- **绿背景（14–15页）**：演员口播素材保持背景不变，后期抠像；不因此添加手机屏幕展示。
- **舞台、沙发、正面播报（18–20页）**：参考图已有场景时不重复描绘，只补动态与台词。舞台位置不代表必须写段子。
- **自拍／回复评论（19、21页）**：可以更像对熟人解释。镜头轻微晃动、走路或一镜到底仅按本条要求采用，不覆盖其他口播或绿背景的稳定机位规则。
- **白板（20页）**：演员看向已有内容、再看镜头解释；准确文字与数字可后期制作，不指望视频模型自动生成无误的数字表格。
- **动画角色（24–25页）**：夸张动作与图形效果来自明确案例，不能默认套给真人。复杂金币、立体数字、Logo和火箭等可列为后期效果建议，是否生成由用户决定，不能因学习旧稿自动添加。

## 声音、动作和镜头怎样配合

1. 一轮问答包含“提问—接收—回答—对方反馈”，压缩空话，不把接收和反应全部删掉。
2. 画外音提问者、镜内人物、客服、内心独白和合声独立标注。正常情况下只有当前说话的人做对应口型，倾听者用简短反应；合声时明确谁一起说哪一句。
3. 每个镜头抓一个主要行为：整理物品、抬头回答、停手确认等。多个人同时挥手、点手机、转头、走动会增加不必要的复杂度。
4. 用事实替换旧稿的笼统词：“表演到位／演技在线”改为具体看向谁、停多久、眉眼和手势怎样变化；“动作夸张”只落实在需要的反应点。
5. 镜头以用户参考图与要求为准。固定景别、分屏、一镜到底等可以是本条约束；不要把每句台词都切一镜当作默认。
6. “无字幕”是现有默认，PDF也有明确加字幕的个别案例；两者各自适用，不能拿旧案例覆盖当前请求。动画特效、文字、Logo和手机界面同理。
7. 音效绑定明确触发点，口播节奏仍靠台词与表演。用户要干净抠像素材时，将装饰音效与图形留作后期建议。

## 30／45／60秒以内的安排

### 时长与信息量

目前默认30秒以内，支持用户后续指定45秒以内或60秒以内；较短的明确秒数优先。长度是成片上限，可拆多段生成再剪辑，不假定模型支持一次完整生成。

| 上限 | 组织重点 | 可选内容安排 |
| --- | --- | --- |
| 30秒以内 | 一个需求、一次主要转折、少量相关卖点 | 快速切入 → 一个核心问题／简短冲突 → 产品回应与反应 → CTA |
| 45秒以内 | 在短版基础上增加理解与反馈 | 多一轮关键追问，或一个清楚算例，或更完整的反转反应 |
| 60秒以内 | 同一主线展开充分 | 交代必要前因 → 推进问题 → 逐层说明 → 人物决定与CTA |

不是所有30秒都必须冲突、所有45秒都必须算例、所有60秒都必须剧情。口播依信息顺序推进，剧情依事件因果推进，采访与客服依问题推进。

### 估算与修正

先预留表演、动作、换人和必要停顿，再估口播容量。粗估总时长＝各段实际发音所需时间之和＋非重叠动作／停顿时间。能与对白自然同时进行的简单动作不重复计时；只能依次发生的动作必须另留时间。

英文可先用每分钟约120–160词作粗估区间，不当作地域标准或成片承诺。金额和利率需展开为实际读法后计量；中文或其他语言另按对应读法估算，不能套英文词数。用户已有指定语速或试读音频时，用它替代此粗估。

- 30秒的纯对白理论容量约60–80个展开后的英文词，但反应、数字和换人会减少可用容量；因此不能把80词当作安全目标，更不能默认“100词＝30秒”。
- 更长版本也不能直接按比例塞满词数；先决定新增内容是否让观众理解得更好。
- 多人轮流讲话不增加总容量；两人同时说同一句合声只占一次时间，不分别相加。
- PDF里“15秒／30秒完成所有台词”的标注是目标，不是经过音频测量的结果；未试读不能宣称已经验证可读完。
- 新写文案若超时，先删重复表达、合并相近卖点、减少完整算例，保留核心需求、关键反应与CTA。
- 锁定原文且必须满足时限时，不直接删句、漏词或挤成不可理解的语速；明确说明冲突并给可比较的精简／延时方案，由用户决定。

## 从旧稿中隔离的事实与错误

学习内容结构，不把历史文件当作最新产品资料。不同页同品牌出现过不同利率、额度与到账时间，中英文列也有金额不一致的例子（如12页）；它们不能合并成一个默认产品档案。

还款示例需要当前项目的计息规则、天数及费用支持。例：第7和32页“5,000 Kwacha、3个月、利息364”的组合，不能仅凭其写在脚本里就默认正确；复用时应重新核对。无需在每次写作中复述所有历史问题，只有当前要用的数字才校核。

“咖啡价格”类比（12、26页）保留生活化写法，但须明确比较的是哪个金额、哪个周期的利息和哪种价格；无条件时不能作为所有借款都成立的说法。“换链接必提额”“全部问题都解决”“必然到账”等也不能随案例自动继承。

本次只吸收用户明确要求的可复用写法与时长偏好；旧稿中的演员年龄、机位、字幕、特殊动作、品牌和图片修改指令，不自动成为所有新脚本的要求。

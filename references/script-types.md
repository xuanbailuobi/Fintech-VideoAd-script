# 脚本分类与旧稿提炼

## 使用方式

按当前主要表达形式选择以下小节。结构是可调整的写法，不是每条必须包含的步骤。用户指定剧情、原文、顺序和特殊格式优先；分类以后可变，混合类型保留主次。不从历史脚本继承产品事实。

## 1. 口播类

**定义：** 没有正在演出的故事事件，一人或多人直接讲产品卖点。可以对镜头讲、轮流接话、问答式讲解或分享经历。讲述过去遇到困难仍可属于口播；只有把事件演出来并推动剧情时才考虑剧情类。

**常用结构：** 痛点问题 → 放大或确认需求 → 引入产品 → 少量相关卖点 → CTA。开头多半提出痛点，也允许直接提问、对比、否定式排比或经历引入，不规定每条必须同样开头。

**旧稿可复用手法：**
- “今天急需一笔钱，你会怎么办？”接“亲友也帮不上呢？”：把观众带进一个选择问题，再给产品选项，不必把借钱过程演成剧情。
- 多次提方案、连续“No”或“Not worth it”，最后介绍产品：重复建立节奏，最后一次改变内容或语气，不让每次反应完全相同。
- “生活突发变故／失去客户／房租到期”第一人称讲述：短视频只留关键困难，尽早进入产品，避免堆多个悲惨事件挤掉卖点与CTA。
- “Credit checks? / Collateral? / Paperwork?”短问短答：这是文案节奏，只有产品确实支持时才保留对应回答。

**表演与生成：** 用目光、轻微手势、停顿、重音和句式变化组织信息。多人出现并不需要增加矛盾；一人自问自答也不自动变成采访。对镜头说话可保持中景，不强制多次切镜。

### 口播素材形式：自然场景／绿背景抠像

口播主分类不变。用户可要求自然场景中的成片口播，或用于后期抠像合成的绿背景人物素材；后者不需要在生成阶段完成最终广告背景。

默认流程为“用户生成并提供演员图 → 依据图中演员补台词与表演提示词 → 用户图生视频 → 用户后期抠像与合成”。写提示词主要描述图片之外的动作、表情、说话节奏和必要连续性，不重复堆砌外貌、服装或设备参数。

绿背景素材遵循主文件中的专门规范：均匀纯绿色、固定机位、稳定景别、自然适度手势、主体不意外出框、口型同步、无额外场景与文字。用户只要素材时不强制加转场、布景或多镜头。按用户要求保留整段口播或分段生成，不保证未验证的单次生成时长。

提示词形态示例（按实际图片和文案替换）：

> 保持参考图演员形象、服装及半身构图。固定机位，均匀纯绿色背景全程保持不变。演员看向镜头，先抬眉提出问题，随后轻轻点头介绍产品，右手在胸前做一次小幅强调手势，双手不越出画面。按原文完整说出下方台词，口型同步。无字幕、Logo或背景道具。

这里只是动态描述示例，不默认添加手机、具体外貌或新的服装；手机屏幕是否展示单独看用户要求。

## 2. 剧情类

**定义：** 人物在具体事件中有需求和阻碍，动作或信息改变局面。重点是“事情发生了什么”，而非演员轮流读卖点。

**常用结构：** 立刻可见的冲突 → 主角尝试或阻碍升级 → 产品相关转机 → 双方反应／反转 → 必要产品信息与CTA。

**旧稿原型：房东催租。** 房东把包推给租客并赶人 → 租客请求宽限被拒绝 → 获知资金变化 → 租客抬头回应 → 房东从呵斥转为主动帮拿包 → 主角向观众推荐。最大记忆点是同一人物前后的态度、动作和声音反差。

**创作要点：**
- 明确人物关系、场景位置和道具因果，一条短片围绕一件事，不增加无用支线。
- 产品转机应与前文需求连上；已有申请后的通知和现场刚开始申请是不同时间逻辑，不混写。
- 反转通过可见行为兑现：房东从指向出口到收回行李，主角从低头求情到抬头说话；不只写“瞬间变脸”。
- 结尾允许直接口播，仍可归为“剧情类，结尾口播”。不为了讲更多参数压缩掉关键反应。
- 旧稿中有屏幕展示，是当时用户明确指定的版本；改成无屏幕版时通过提示音、人物看手机后的反应和对白承接，不自行恢复绿幕。

## 3. 街头偶遇

**定义：** 相遇或搭话触发交流，由路人、熟人或朋友发现问题并推荐。核心是相遇的理由与交流的自然性；并非只要站在街头就算此类。

**常用结构：** 街头可见困难／异常举动 → 他人注意并搭话 → 主角说出需求 → 推荐及必要追问 → 反应与CTA。

**旧稿原型：连续打电话借钱失败。** 前两位亲友拒绝，第三位直接挂断 → 主角看着手机停住 → 经过的人注意到并询问 → 给出产品选项 → 主角从尴尬到感兴趣／采取行动。

**创作要点：**
- 给推荐者合理的进入理由，如听到叹气或认出朋友；不要毫无缘由冲进来背全部参数。
- 连续失败可用台词长短、挂断声和反应升级，不要求三通电话；字数装不进时减少重复，不把长对话硬塞进数秒。
- 亲友通话的另一端可用画外音，不必生成多个额外人物；推荐者是不是熟人要前后一致。
- 即使有电话，这也不属于电话客服；即使有问答，也不自动属于采访。
- 可归为“街头偶遇，带剧情开场”，用户另有分类时跟随用户。

## 4. 采访

**定义：** 明确的采访者与受访者关系，提问—回答—追问是主要推进方式。可以街头采访，也可以固定场景采访；话筒不是唯一识别标准，不默认要求话筒。

**常用结构：** 有回答空间的痛点或选择题 → 受访者说自己的情况／想法 → 采访者针对回答追问 → 顺势引入相关产品信息 → 自然反馈与CTA。

**创作要点：**
- 开头问题要容易理解和回答，避免一句内问多个产品参数。
- 后续问题承接上个回答，不把产品介绍机械切成互不相干的问句；受访者不必每次只说“Wow”。
- 分清谁知道产品、谁提问、谁讲卖点；不要让受访者突然变成客服或让主持人凭空获知个人借款结果。
- 可选单人采访、多人回答同一问题、短追问等形式，不默认生成大量路人、换景或证言。
- 设计广告演绎时不把虚构回答写成已发生的真实采访记录或真实用户证明。

## 5. 电话客服（素人主动来电咨询）

**定义：** 普通用户给产品客服打电话，围绕资金需求、额度、利息、手续或期限咨询。不是客服主动外呼，也不是亲友借钱通话。

**常用结构：** 来电者先提出具体问题 → 客服先回应当下问题 → 来电者产生下一层疑虑 → 客服解释 → 对方可见反馈 → 行动引导。三连问只是可用节奏，不固定题数和顺序。

**旧稿原型：**
- 情侣中女孩咨询费用需求、男友陪伴，另一场景的客服回应；听到额度后仍担心利息，再询问期限，反应从担忧转为放松。
- “想借较高额度但希望利息低”→“需要抵押吗？”→“申请麻烦吗？”：问题由上个答案推动，客服用简短回应建立信心，再集中解释必要信息。
- 对额度产生疑问、保持通话并操作、继续问利息：适合边咨询边反馈，但不能虚构“换链接一定提额”或把额度上限等同于个人必获额度。

**表演与生成：**
- 写清两端不在同一空间，不互相对视、递手机或发生跨空间动作。可交替展示来电者与客服，也可让客服仅画外音，按用户设定选择。
- 陪伴者可在来电者身边回应，但不抢成第三位主要讲解者。
- 客服回答后给来电者短反馈，再进入下一问；笑容、点头、停顿或强调随回答变化，不机械重复。
- 使用手机或耳麦不需要展示屏幕；不因“打电话”自动添加绿幕、手机UI或到账镜头。
- 声音可用轻微电话音色区分另一端，以清楚可懂为前提；提示音只在拨号、接通、挂断或实际通知处使用。

### 复习后沿用与修正

- 用户的最新要求覆盖旧示例：旧稿常带绿幕，不代表以后默认带绿幕；最新通用约定仍为明确要求手机屏幕展示才添加。演员背景绿幕是另一种素材形式，不能混为一谈。旧稿曾建议至少3秒，后续统一约定约2秒；按本次用户需求安排展示时长，保留固定角度、清晰四角和独立展示镜头等有效经验。
- 安卓手机要求来自赞比亚项目的明确反馈；保留该适用范围，不把推荐机型视为所有市场的统一设备。
- “30秒、100词以内”在旧稿是具体改稿要求，不升级成所有广告的固定字数。数字和缩写展开朗读会更长，考虑停顿与反应，不能仅凭词数保证时长。
- 旧助手出现过自行加入卖点、把放款时间改成未经确认数值、改掉用户要保留的比喻等情况；学习结构与节奏，不把这些旧输出当作已验证资料。换产品时核对事实，保留原意，必要修改说明理由。
- 同一表达手法可以跨类型复用：问答不是采访的充分条件，经历不是剧情的充分条件，手机也不是客服类的充分条件。分类用于选结构，不限制创意。
